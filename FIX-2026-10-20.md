map lone Resp.Co codes WDV->WFD, HDV->HAL. Rules-v2 R1 corollary
(row 106: WDV code, company UNPROVEN) says a lone code proves nothing.
Reconciliation is at the ingest/normalisation layer, extractor
untouched:

1. data/ingest_adjudicated.py normalise_company(): WDV/HDV/TOD ->
   UNPROVEN (fixture row 106 already UNPROVEN; guard is forward cover).

   never-company code FAILS the build loudly (never published as a
   misattribution).
3. build_db _matrix_source_page(): an adjudicated row carrying a lone
   code FAILS the build (ingest must normalise first).
4. build_db insert loop: last-gate map of any residual lone code ->
   UNPROVEN (defense in depth; workbook rows included).
5. API: ?company=WDV/HDV/TOD answers 400 with the R1 citation.
6. jev_consume COMPANY_TOKENS: WDV/HDV/TOD deliberately unmapped.

Consequence for the old corpus: June2026-extracted.json (224 rows,
pre-v2) stays quarantined behind --include-extracted; any extracted
row whose only company evidence is a Resp.Co code can no longer enter
a fresh build. No silent drops anywhere: every refusal is an exception
with the row attached.
