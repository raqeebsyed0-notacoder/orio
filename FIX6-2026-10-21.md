# FIX6 report — 2026-10-21 (Report-day dropdown illegible in dark shell, card t_31edfb22)

Source: Founder screenshot, live dark shell, 2026-10-21. No commit in this
card — orchestrator re-gates, then commit+push. Demo tier only.

## 1. Defect

The Report-day picker was a native `<select>` (Latest + 92 dates). The popup
renders in OS chrome — white background, pale-grey unselected options
(~1.5:1 contrast) — illegible against the dark shell theme; only the
blue-highlighted selected row was readable. The control "worked" but a user
could not read the choices: accessibility + usability FAIL in the real
shell. The SSR harness could never see this class of defect (native popups
do not render in DOM captures), so this card required an interactive
headless-Chrome harness with a dark-theme page.

## 2. Fix (plugin.js only; no data/API change)

New `DayPicker` component (`desktop/plugin.js`, next to `OrioPage`):
button trigger + popover listbox, both pure theme-var DOM
(`--foreground` text on `--ui-bg-elevated` surface — the same pair as the
nav buttons, so the OPEN list inherits the shell theme and stays readable
in dark mode; zero hardcoded colors):
- Trigger shows `Latest (date)` or the selected date; `aria-label="Report day"`,
  same explanatory title as before, `aria-haspopup="listbox"`.
- List = Latest + report dates DESC (93 rows), `role="listbox"` /
  `role="option"`, selected row marked with `aria-selected` + accent color +
  bold + visible checkmark; opens scrolled to the selected row.
- Behavior identical: selecting drives `$day` + `storageSet('day', v)`;
  Latest = `''` (server default); `/meta` validation and the stale-day
  reset in `OrioPage` are untouched.
- Dismiss: click-outside + Escape (capture-phase document listeners,
  removed on close/unmount).
- Keyboard (honest scope, as carded): trigger is a real `<button>`
  (Tab-focusable; Enter/Space toggles); while open, ArrowUp/Down moves the
  highlight, Enter commits, Escape/Tab closes; focus stays on the trigger
  throughout (no roving tabindex into the list).
- F2 discipline kept: array children through `jsxs()`, per-child keys as
  the third `jsx`/`jsxs` argument (the removed `option` spread-keys from
  the FIX4 residuals are gone with the element itself).

The smaller `color-scheme: dark` alternative was rejected without a proof
attempt: it depends on the shell's Chrome version honoring it for native
popups and leaves the list uncapturable in DOM screenshots — the same
blind spot that hid this defect. The custom listbox is screenshot-verifiable
by construction.
